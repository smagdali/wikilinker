# Wikilinker Internationalisation Design

> **SUPERSEDED 2026-04-14.** See [2026-04-14-i18n-design.md](2026-04-14-i18n-design.md) for the current plan. Key revisions: Safari uses one Xcode project with `Localizable.strings` (not N projects); screenshots generated from synthetic article templates (not live news URLs); about page stays English-only; `--bloom` flag removed.

Date: 2026-03-10

## Goal

Publish Wikilinker in the top 20 Wikipedia languages across all three browser stores (Chrome, Firefox, Safari). One extension per language, each with its own bloom filter, skip words, UI strings, store listing, and screenshots.

Three tiers of matching complexity:

- **Regex languages** (15): Latin, Cyrillic, Devanagari, Arabic, Persian. Current regex approach works with Unicode character classes (`\p{Lu}`, `\p{L}`). Each language needs its own skip words.
- **CJK languages** (3: ja, zh, ko): Use `Intl.Segmenter` for word boundaries. Match segmented words and 2-3 word sequences against the bloom filter. No uppercase/sentence-start rules.
- **RTL languages** (2: ar, fa): Regex works (these languages use spaces). Popup UI needs `dir="auto"` on text elements.

Notes:
- Chinese Wikipedia is blocked in mainland China but has significant traffic from Taiwan, Hong Kong, Singapore, and diaspora.
- Chrome Web Store also requires VPN in mainland China.

## Approach

Monorepo with parameterised build. Single source of truth for all shared code. The build script takes a `--lang` flag and produces a complete extension for that language.

## Data Pipeline

### 1. Extract pageviews per language

Modify `build-pageview-ranking.sh`:
- Add `--lang fr` flag: changes awk filter from `$1 == "en.wikipedia"` to `$1 == "fr.wikipedia"`
- Add `--all-langs` mode: single pass through each bz2, extracts all 20 languages simultaneously
- Output: `i18n/{lang}/titles-ranked.tsv`
- Daily bz2 dumps are already cached (~20GB) — no re-downloading needed

### 2. Build bloom filter per language

Modify `build-bloom.mjs`:
- Add `--lang fr` flag
- Reads `i18n/fr/titles-ranked.tsv`, writes `i18n/fr/entities-bloom.bin`
- Same parameters: 1M titles, 0.01% false positive rate, ~2.4MB per filter

### 3. Build skip words per language

New `scripts/build-skip-words.mjs`:
- Start from English skip words as a template
- Use Claude API to translate the English list and augment with language-specific additions (articles, particles, common words that happen to be Wikipedia titles)
- Write to `i18n/{lang}/skip-words.json`
- Validate by running matcher with `--debug` against sample pages

### 4. Generate translations

New `scripts/translate-strings.mjs`:
- First step: produce a simplified, non-idiomatic English version of all UI strings and store listing copy (short declarative sentences, no slang or cultural references)
- Feed simplified English to Claude API to generate all 19 translations
- Output: `i18n/{lang}/messages.json` (chrome.i18n format) and `i18n/{lang}/store-listing.json`

## Matcher Changes

### Unicode regex upgrade (regex languages)

Current candidate regex uses `[A-Z]` for uppercase detection. Change to:
- `\p{Lu}` for uppercase letters (covers Latin, Cyrillic, Greek)
- `\p{L}` for any letter
- This handles German (ÄÖÜ), Russian (А-Я), Turkish (İŞ), etc.

Skip words loaded from `i18n/{lang}/skip-words.json` instead of hardcoded array.

### CJK matcher (ja, zh, ko)

New matching strategy using `Intl.Segmenter`:
1. Segment extracted text into words using `new Intl.Segmenter(lang, { granularity: 'word' })`
2. For each word segment, check the bloom filter
3. Also check 2-word and 3-word concatenations (for multi-word titles)
4. No uppercase detection, no sentence-start filter, no `isPartOfLargerPhrase`
5. First-occurrence-only and deduplication rules still apply

`Intl.Segmenter` support: Chrome 87+, Safari 15.4+, Firefox 125+ (all within our target versions).

### RTL support (ar, fa)

Regex approach works since Arabic and Persian use spaces. Add `dir="auto"` to popup text elements. Wikilinks render correctly in RTL context — the browser handles bidi layout.

## Extension Build

`node extension/build.js --bloom --lang fr`:

1. Copy `extension/` to temp build directory
2. Swap in `i18n/fr/entities-bloom.bin` as entity data
3. Swap in `i18n/fr/skip-words.json` for the matcher
4. Create `_locales/fr/messages.json` from `i18n/fr/messages.json`
5. Patch `manifest.json`:
   - Set `default_locale: "fr"`
   - Set `name: "Wikilinker (Français)"`
   - Set localised `description`
6. For CJK languages, include the Intl.Segmenter matcher variant instead of the regex matcher
7. esbuild bundle
8. Output ZIP to `build/wikilinker-fr.zip`

### Safari / Xcode

Per-language Xcode projects are generated programmatically from a template:
- Only runtime files in Resources/ (manifest.json, popup.html, popup.js, styles.css, dist/, icons/, _locales/)
- No build artifacts (src/, scripts/, screenshots/, promo files, README, store-listing)
- pbxproj generated, not hand-maintained — avoids the "Invalid Signature" errors from stale file references
- Per-language bundle IDs (e.g. `org.whitelabel.wikilinker-fr`)
- All targets use development team `86H54WCPYP`

## Screenshot Generation

`scripts/generate-screenshots.mjs` using Playwright:

- Each language's `sample-urls.json` contains 2-3 URLs from major news sites in that language (e.g. Le Monde for French, Der Spiegel for German, El País for Spanish)
- Articles chosen to be uncontroversial: science, geography, culture, sport
- Script navigates to each news article, runs the Wikilinker extension to inject Wikipedia links, then takes screenshots showing the extension in action
- Captures at required dimensions:
  - Desktop: 1280×800 (Chrome/Firefox stores)
  - iPhone: 1284×2778 (App Store)
  - iPad: 2048×2732 (App Store)
- Promo images (440×280 and 1400×560) rendered from HTML templates with localised text
- Output to `i18n/{lang}/screenshots/`

## Publishing Pipeline

### Chrome Web Store

- Use [Chrome Web Store Publish API](https://developer.chrome.com/docs/webstore/using-api)
- Each language gets its own listing (requires one-time registration of 20 extension IDs)
- `scripts/publish-chrome.sh --lang fr` uploads ZIP + localised store metadata
- Credentials via environment variables

### Firefox AMO

- Use [AMO Signing API](https://extensionworkshop.com/documentation/develop/web-ext-command-reference/#web-ext-sign)
- Upload signed XPI per language
- Store metadata (name, description) set via API
- Per-language addon IDs in `browser_specific_settings.gecko`

### Safari App Store

- `xcodebuild archive` + `xcrun altool --upload-app` per language
- Each language gets its own App ID and bundle ID
- Archive requires Apple Distribution certificate (not Development)
- Both macOS and iOS targets per language

### Orchestration

`scripts/publish-all.sh` wraps all three store pipelines:
- Builds all 20 ZIPs/archives
- Uploads to Chrome, Firefox, Safari in sequence
- Store credentials from environment variables
- Logs results per language per store
